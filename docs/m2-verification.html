3. 本轮新发现

F1 · $ 不是"绝对引用"，是 isSaved会写出必挂实现

规格（M2-06 / 附件 G.1）说 $ 是"整格绝对引用前缀"，机制是"剥掉一个 $ 后交给 CellLocation.parse"。 前半句对，但漏了关键一半：源码里 $X 走 new CSVariable(cell, true)、 无 $ 走 (cell, false)，而 calculate() 里这个布尔是 current = isSaved ? cs.getSavedCurrent() : cs.getCurrent() （CSVariable.java:31-44,127）。它切换的是"用哪个 current 解析"，不是"引用是否绝对"。

我写了独立探针在同一次运行内并排实测（数据集 North/100、East/200、South/150）：

表达式行2行3行4判读
B2100200150标量相对
$B2100200150与 B2 完全一致
$B2*3300600450标量下 $ 无差别
sum(B2:B4)100100100常量
sum($B2:B4)100200150逐行 ≠ 上一行
sum(B2:B2) / sum($B2:B2)100200150同格，无差别

影响：若按"剥掉 $ 当普通引用"实现，sum($B2:B4) 会算成 100/100/100， 而基准要求 100/200/150 → golden 必挂。断言的根因在 Sum/Select/Average/Max/Min 会调用 saveCurrent()/resumeCurrent()（Sum.java:150,190），此时 saved ≠ current，$ 才显形。

已固化：tests/fixtures/VerifyDollar.java（70 行，8 组表达式并排）作为永久复现证据； 规格 M2-06、§5、§8 与附件 G.1 均已改写。

F2 · M2-13 把 450 挂到了错的数据集上判据与基准相反

规格原文要求 ds1.sum(qty) = 450。基准实测（engine_sum.expected.json，我已重新生成并逐字节比对）：

(2,5) ds1.sum(qty)  => 100   # 被扩展格引用 → 逐行
(2,7) ds2.sum(qty)  => 450   # 未被引用 → 全量

而 GenEngineFixtures.java:155-161 明确写着 ds2 是"identical content but no extending cells referencing it" —— 两个数据集内容一模一样，差异纯粹来自"是否被扩展格引用"。所以正确表述是 ds2 得 450、ds1 得 100， 原表述把两者写反了。若照抄，实现者会写出断言 ds1=450 的测试，与基准直接冲突。

已修正为「ds2.sum(qty)=450，而被引用的 ds1.sum(qty)=100（两者数据集相同）」。

F3 · engine_ext 无力区分 17 / 18 / 19M2-15 只证了一半

该夹具的设计意图是覆盖"extendMode 16/17/18/19 四态改写"，但四个声明被放在同一行，实测结果：

(2,1) 声明 16(默认) => 运行时 extend=18, sub_cells=5   ✅ 16→18 改写成立
(2,2) 声明 17       => 运行时 extend=17, sub_cells=1
(2,3) 声明 18       => 运行时 extend=18, sub_cells=1    ⚠ 与被吞的 17/19 无法区分
(2,4) 声明 19       => 运行时 extend=19, sub_cells=1

extend 值分布 = {16:8, 17:1, 18:2, 19:1}    任何 List 类型值：无

即：16→18 改写与行数公式成立（3+5−1=7 ✅），但"17 必须产出整列 List"以及 18/19 的独立行为 没有任何基准能证明。这个夹具改不动实现者的错——它会直接放过一个把 17/18/19 全当同一种处理的实现。

建议：拆成三个夹具，把 17/18/19 分别放在不同的行（各自独占扩展包络），并至少给 17 一个可断言的 List 值。

F4 · calculated.cells[].source 是可选键，M2-09 的"逐格断言"前提不成立断言会误挂

M2-09 要求"calculated 段必须逐格断言（值 + type + source 六个子字段）"。但实测：

engine_sum   cells=36  (无 source = 0)
engine_ext   cells=24  (无 source = 12)   ← 一半的格没有 source
engine_expr  cells=20  (无 source = 0)
engine_pager cells=124 (无 source = 114)   ← 绝大多数没有 source

实现者若按字面写"每格必须有 source 且含六个子字段"，会对着一半以上的格子取到 None/null 而误判失败。 另外规格 §7 自身也有个笔误：括号里列了 src_row/src_col/row_merge/col_merge/extend/sub_cells 六个名字，却写"五个子字段"。

已修正计数为六个，并在规格中标注 source 为可选键。
