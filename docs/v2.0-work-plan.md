# v2.0 工作计划

> 基线：`v0.7.0-v2-defaults`（2026-10-17）
> 前提：默认 CLI / runtime / server 已切 JSON-only；`.rpx` 通过 `legacy-rpx` feature 可选启用。
> 关联：[JSON canonical ADR](adr/0001-json-canonical-format.md)、[legacy 退役指南](format/rpx-legacy-retirement.md)。

## 1. 目标

把“默认 JSON-only”从**构建能力**推进到**可交付的 1.0**：

1. legacy 路径隔离干净，测试/发布不再依赖默认 `.rpx`。
2. 已有目录库和 RPX 资产有可回滚的迁移工具。
3. Web 端达到可交付的认证/E2E 覆盖。
4. 明确 PDF、`.rpxpkg`、schema v2 的取舍，不做无依据扩张。
5. 形成 1.0 的兼容性、发布与回滚流程。

## 2. 工作流与优先级

| 优先级 | 工作流 | 交付物 | 验收 |
|---|---|---|---|
| P0 | WP1 legacy 隔离收尾 | 独立 legacy 测试目标/CI job；默认测试矩阵 | 默认与 legacy 两套测试都绿 |
| P0 | WP2 库迁移工具 | `rpx format migrate`（dry-run/commit/rollback）+ 备份 | 真实库迁移成功且可回滚 |
| P0 | WP3 默认构建硬化 | CI 矩阵、安装包、发布脚本 | default/legacy 安装均可运行 |
| P1 | WP4 Web 认证与 E2E | 登录/鉴权、Playwright 主流程 | 未授权/授权路径都有 E2E |
| P1 | WP5 PDF 出口决策 | 补 PDF 或改掉错误文案 | 能力与文档一致 |
| P1 | WP6 性能与上限 | SQL 行数上限/流式选项、大模板基准 | 有阈值、有超限错误 |
| P2 | WP7 `.rpxpkg` | 单文件包 zip + 读写 + 迁移 | 往返/校验/失败清理 |
| P2 | WP8 schema v2 | 迁移映射与兼容 reader | 只在有迁移工具时发布 |

## 3. 建议排期

### Sprint 1（约 1 周）：收尾与迁移工具

- 把 runtime legacy 测试迁到独立 `tests/legacy/` 或 Cargo test target（减少 feature 散落）。
- 补 `rpx format migrate`：
  - `--dry-run` 列出可迁移/冲突/不支持；
  - `--backup` 生成可回滚快照；
  - 成功后写 `.library.json` 迁移标记；
  - 失败不修改原库。
- CI 增加：
  - `default` job（无 legacy）
  - `legacy` job（`--features legacy-rpx`）
  - 两套都跑 40/40 + 23/23 门禁。

**验收**：新建库、旧库、坏包三种场景；迁移失败可回滚。

### Sprint 2（约 2 周）：发布与 Web 基础

- `make install-local` / `install-local-legacy` 发布冒烟脚本化。
- Web 登录/鉴权：
  - 明确 token/session 模型；
  - 未授权 API 返回 JSON error；
  - Playwright 覆盖登录、保存、运行、查看结果。
- PDF 决策：
  - 若补 PDF：走服务端导出，跑同一页映射；
  - 若不补：统一改 `print-xlsx` 错误文案，并在 doctor 中声明能力。

**验收**：Web 主流程 E2E 绿；PDF 能力在 CLI/doctor/文档一致。

### Sprint 3（约 2 周）：性能与可选包格式

- SQL 取数行数上限/流式选项；超限显式错误。
- 大模板/大结果基准（时间、内存、产物大小）。
- `.rpxpkg` 原型：
  - zip: `manifest.json` + `template.json` + `data/` + `assets/`；
  - 路径穿越、zip bomb、失败清理测试；
  - 与目录库互转。
- 评估 schema v2，不默认启用。

**验收**：性能阈值写入文档；`.rpxpkg` 能往返且安全失败。

### Sprint 4（约 1 周）：1.0 发布

- 版本/CHANGELOG/迁移指南/回滚手册。
- CI 全矩阵、安装冒烟、e2e、JSON-only smoke。
- 生产检查：日志、错误码、鉴权、数据目录权限。
- 1.0 tag + 发布说明。

## 4. 测试矩阵

| 场景 | 默认 | legacy |
|---|---|---|
| CLI 安装/help | JSON-only 命令集 | 含 format/compile/import-rpx |
| 40 个产品 RPX | 不读 | Preserve + 快照字节 |
| 23 个引擎夹具 | JSON fixtures | JSON + `.rpx` 对照 |
| 库读写/运行 | JSON | JSON + 导入 RPX |
| Web API/E2E | 必跑 | 可选 |
| 依赖图 | 无 `rpx-core` / `legacy-rpx` | 允许 |

## 5. 风险与回滚

| 风险 | 缓解 |
|---|---|
| legacy 测试漂移 | 双 job；`.rpx` 测试只放 legacy target |
| 库迁移丢数据 | 先备份；dry-run；失败不落盘；可 restore |
| Web 鉴权破坏现有调用 | token 可选迁移期；错误 JSON 化 |
| `.rpxpkg` 安全 | zip 路径/大小/条目数限制；失败清理 |
| schema v2 过度设计 | 先做迁移映射与兼容 reader，不默认切 |

## 6. 待确认决策

1. Web 登录/鉴权是否纳入 1.0 必须项？
2. PDF 是补出口，还是只修文案？
3. `.rpxpkg` 是否进入 1.0，还是 1.x？
4. schema v2 是否只做评估，不排期实现？
5. 1.0 兼容承诺：`.rpx` legacy feature 保留多久、默认安装是否永远 JSON-only？

## 7. 建议下一步

先做 **WP1 + WP2**：

1. legacy 测试独立 target；
2. `format migrate` dry-run/backup/rollback；
3. CI 双 job；
4. 用真实库跑一次迁移演练。

这三项完成后，再并行 Web 认证/E2E 与 PDF 决策，风险最低。
