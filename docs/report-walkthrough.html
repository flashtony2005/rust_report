闭环（设计器）：面板改 JSON → 导出 JSON → 重渲染（数据集文件随 multipart 一并上传）。

数据源 = 定义 JSON 的 datasets[]（SQL 或 CSV 文件）， 经表达式在格子里取值；报表设定 = print_setup / extend_mode / row_props / col_props / grid（不产数据，定形态）； 报表展示 = POST /api/render 渲染出的 Univer 快照在画布上的样子。 一句话：数据源决定「有哪些行」，设定决定「长什么样」，展示就是引擎把两者算完的结果。

第一步数据源（datasets[]）

1.1 两种形态（互斥）

形态字段语义实例
sql {dsn, sql} SQL 数据集：dsn 是连接名（不是连接串），由服务端启动参数注册； sql 是查询语句 ds1 ← SELECT name, salary FROM emp ORDER BY id
file {file_name, encoding?} 文件数据集（CSV）：file_name 须与渲染时上传的 CSV 文件名 逐字一致；encoding 可选，缺省 GBK engine_crossalign.csv

⚠ 两者互斥（都给 / 都不给都报错，校验镜像服务端 parse_dataset）； 数据集名重复只告警不拦截——服务端对表达式按名字绑定不做重名校验， 前端若拦就是「无出处的严」。

1.2 dsn 从哪来：服务端启动参数注册

产品把连接三要素放在配置文件（raqsoftConfig.xml 的 <DBList>）， 不进 .rpx；Rust 版同构——serve --datasources <path.json> 在 启动期建池（配置错误快速失败，不带病服务），引擎与快照层只见 dsn：

{
  "demo": "sqlite:///F:\\project\\report\\rpx\\target\\sqlite_demo.db"
}

字符串形态 = 完整连接串（凭据内嵌）；对象形态 = 三要素分写。 凭据不进模板、不进日志（DataSourceRegistry 手写 Debug）。

⚠ SQLite 连接 URL 有坑（实测矩阵，rpx-ds/tests/url_probe.rs）： sqlite::memory: ✅；sqlite:F:\abs\path / sqlite:///F:\abs\path ✅（文件库）； sqlite://F:\abs（两斜杠）❌——host 被剥、fetch code 14；相对路径 ❌。 Windows 下文件库务必走与 server 同盘符的绝对反斜杠路径。

1.4 表达式词汇表：怎么在格子里用数据

表达式形态语义出处
ds1.select(name)纵带展开 按数据集行数向下展开，每行取该列 sqlite_demo.json
ds1.select(name, dept==A3)带过滤 条件表达式过滤后展开（A3 = 当前格上方的值，主子表关联的常用姿势） cross_dept_band
ds1.select(item, id==1, 1)过滤 + 偏移 三参形态：列、条件、偏移量 cross_emp_bonus
ds1.select(item:-1)DSOffset 带偏移读（负偏移：向上取前 N 行） cross_emp_bonus
ds1[2].qtyDSOffset 下标 Root 态按行号取值（1 起）；越界（[0]/[9]）返回 Null 不报错； 非整数下标显式报错 expr/tests_offset.rs
ds1.qtyDSVariable Row 态取当前行该列；Root 态取首行 expr/dsfn.rs
ds1.sum(salary)DS 聚合 整列聚合（另有 count / avg / max / min）；纯函数形态同款 extend_demo.json
@topN参数引用 渲染时注入；声明 ≠ 给值——未登记参数会 400（不是静默取 null） def_params_demo.json

1.5 文件数据集：CSV 随 multipart 上传

区域×产品交叉用例的 engine_crossalign.csv（GBK 编码，3 列 5 行）： region / product / amount。渲染时 CSV 作为 dataset 字段随 POST /api/render 上传，文件名须与 file_name 逐字一致 （少给一个文件会显式报「缺少数据集文件：<文件名>」）。

1.6 校验口径（与服务端逐字一致）

sql 与 file 互斥；SQL 分支 dsn/sql 必填； 文件分支 file_name 必填（encoding 缺省 GBK）。 数据集重名只告警（表达式按名字绑定的歧义提示），不拦截。

第二步报表设定（定形态，不产数据）

2.1 print_setup：16 个开放字段

字段缺省档位（校验镜像 apply_print_setup）
paper_width / paper_height210 / 297f32 ≥0（A4，单位 mm）
left / right / top / bottom_margin19 / 19 / 25 / 25f32 ≥0
row_num_per_page20i32
copy_count1i32
zoom_scale100i16（0..=32767）
table_column_num / layout_rows / layout_cols1 / 1 / 1i16
back_graph_printed / column_repeated_group_header /
full_screen_preview / blank_line_filled		 false × 4bool

面板口径：读方向 = JSON 派生（未声明字段显示契约缺省而非空）； 写方向逐键补丁，值等于缺省 ⇒ 删键（不留冗余键）。 virtual_printer（字符串）契约开放但不做 UI——虚拟打印机是打印链路概念， Web 设计器设它没有意义，不猜。

2.2 extend_mode：纵向 / 横向扩展

vertical（纵扩）行结构放大 N 倍
每个员工占一行
vs
horizontal（横扩）列结构放大 N 倍
每个员工占一列

纵扩的格子带 "extend_mode": "vertical"，横扩带 "horizontal"。 同一份数据、同一句 ds1.select(name)，两种展开方向产出完全不同的报表骨架。

2.3 行列属性与网格尺寸

定义 JSON 的 height/width 单位是 mm（与 .rpx 模板一致： 缺省行高 8mm、列宽 25mm），服务端快照按 96dpi 换算成 px （mm × 96 / 25.4：8mm→30.24px、25mm→94.49px）。 Univer 的 setRowHeight/setColumnWidth 吃 px ⇒ 面板输入显示用 mm，画布落地时换算。 row_props[].break_page 控制断页。⚠ 缩小 grid 前必须先校验越界—— cells[].row/col、合并矩形、row_props 都须落在新网格内，否则服务端 400； 面板显式报错（含首个越界位置），不静默截断、不自动删声明。

2.4 六个面板（右侧停靠，产品 IDE 同构）

面板覆盖补丁方式
样式字体族/字号/颜色/粗斜下划线（7 字段）逐字段补丁，缺省即删键
属性边框四边 / 数字格式 / 旋转读方向从定义 JSON 派生（快照不含这三项）

第三步报表展示（渲染结果）

3.1 渲染管线

POST /api/render（multipart）：report = 定义 JSON 或 .rpx 模板 （服务端按内容分派：RQQR 魔数 → .rpx；首个非空白字节 { → JSON）； dataset = 模板引用的 CSV（可多个）；params = 参数 JSON（可选）。 响应 = Univer IWorkbookData 快照，直接 createWorkbook 上画布。

3.2 快照长什么样

快照的 cellData 是「行 → 列 → 格」的对象矩阵，每格带 v（值）、t（类型：2=数值、4=字符串）、s（样式）； 合并区在 mergeData。下面三张表是真实快照解析出的渲染结果。

定义：表头两格 + 纵带 ds1.select(name/salary) + 末行 ds1.sum(salary)。渲染后 3 名员工各占一行，合计落底：

3.6 编辑 → 导出 → 重渲染闭环

设计器里改单元格 → SheetValueChanged 事件只把 真改过的那一格补丁进定义 JSON（不整体回灌——否则 "0123" 会被 Univer 按数值归一化，静默改坏没碰过的格）→ 点「导出 JSON」下载 → 重渲染验证。 服务端判据：open_bytes(to_bytes(build(json))) == build(json) 逐字节往返。
