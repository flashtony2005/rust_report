# 数据蒋堂讲座研读笔记——对 rpx 的启发（2026-10-15）

> 来源：`https://c.raqsoft.com.cn/tag/Lecture`（数据蒋堂，蒋步星数据计算理论专栏），
> 24 篇全读，HTML 快照与纯文本在 `tests/fixtures/out/lecture/`。
> 结论先行：**对 rpx 最值钱的不是某个算法，而是三套「语义模型」**——分组模型
> （扩展格的理论根基）、JOIN 三分类（多数据集关联的设计图纸）、聚合运算的
> 一般定义（函数面扩展的准绳）。

## 一、讲座地图（24 篇分四组）

| 组 | 篇目 | 一句话主旨 |
| --- | --- | --- |
| 分组理论 | 还原分组运算的本意 / 非等值分组 / 有序分组 / 再谈有序分组 | 分组=把集合拆成子集（返回集合的集合）；聚合是独立步骤；等值分组只是特例，还有对位/枚举/有序分组 |
| 聚合理论 | 非常规聚合 / 迭代函数和自定义聚合运算 / 定位函数和定位计算 | 聚合=「集合为参、返回任意值」；minp/maxp/top 返回记录/集合；iterate 统一一切可遍历聚合；定位函数（pselect/pmax）比选出函数更基础 |
| JOIN 八讲 | SQL 中的 JOIN ① → 有序归并 ⑧ | 等值 JOIN 只有三类（外键/同维/主子），按类简化语法（外键属性化/同维表等同化/子表集合化/维度对齐）并按类提速（地址化/序号化/单边分堆/有序归并） |
| 场景与架构 | 前半有序 / 遍历复用 / BI×3 / SQL 困难源于关系代数 / 对象-事件模式 | 性能靠利用数据特征（有序性/复用遍历）；BI 自助分析软肋在关联查询；根因是关系代数无序集合论 |

## 二、对 rpx 的十条启发（观点 → 落点）

1. **分组=完全划分，聚合是独立步骤**（分组三部曲）。rpx 落点：将来实现
   **分组扩展格**（`ds.group(列)`）时，语义模型必须是「等值分组 → 完全划分
   → 每个子集一个行带」，而非「去重循环」——空组不出现、成员不重复、
   **结果集保持原序**（每组按首次出现次序）。这三条性质可直接写成
   夹具断言与 tripwire。
2. **分组子集应可保持复用**（不聚合先看子集；多聚合值不重复分组）。rpx 落点：
   引擎 `DataSet` 已保留 `selected` 运行时态——将来 group 扩展实现时，
   「行带实例 ↔ 数据集游标（DsCur）」的绑定正是「保持分组子集」的产品化形态。
3. **有序分组 @o（键变化即新组）/ @i（条件成立即新组）**。rpx 落点：这是
   润乾类报表「分组扩展」的高级形态；按纪律先探针后实现，但语义模型先记账
   ——有序分组**不能**转换成等值分组再算（虽然 SQL 那么绕），要原生实现。
4. **对位分组 align / 枚举分组 enum（可重叠 @r）**。rpx 落点：M2-12 函数面
   目前只有 sum/avg/max/min/count 等；这三类分组函数 + minp/maxp/top
   （返回记录/集合）是函数面的自然扩展清单——每个都按「探针 → 夹具 → 实现」
   流程走。
5. **聚合的一般定义：集合为参、返回任意值**（可以返回记录/集合）。rpx 落点：
   `Value::List` 已存在；聚合函数的返回类型不该被「单值」锁死。设计
   `Aggregate` trait 时按「iterate 可描述性」分层：可一次遍历的（sum/count/
   max/min/iterate 系）可以流式；不可的（中位数/distinct 排序）走物化。
6. **iterate(表达式, 初始值) 统一自定义聚合**。rpx 落点：远期若做表达式
   扩展（用户自定义聚合），这是零新概念的方案——SUM/COUNT/MAX/MIN 全是
   iterate 的特例，教学与实现成本都最低。
7. **等值 JOIN 三分类：外键关联（多对一）/ 同维表（一对一）/ 主子表（一对多）**
   （JOIN ②）。rpx 落点：**rpx-ds 多数据集关联的设计图纸**——蓝图 §7 的
   cross 应按三分类建模，而不是通用笛卡尔积过滤；「多对多大概率写错了」
   这条法则可以直接做成校验守卫。
8. **维度对齐（JOIN ④）**：多个数据集向共同维度对齐、互不关心彼此——
   **这正是报表工具多数据集关联的经典难题的产品级答案**。rpx 落点：
   报表里两个数据集（如 `engine_sum` 的 ds1/ds2）各自向维度对齐展开，
   比在 SQL 里 JOIN 好写得多；将来在引擎或 rpx-ds 层做「对齐算子」，
   语义=同维表等同化 + FULL JOIN 的可控版。
9. **外键地址化 / 预关联（switch 指向记录）与有序归并（n+m）**（JOIN ⑥⑦⑧）。
   rpx 落点：`RowSet` 物化到内存后的关联实现选型——事实表×多个维表时
   一次性地址化（HASh 只算一遍、可复用、易并行）；主子表/同维表按主键
   有序时用归并（读一次、内存极小）。这些是 rpx-ds 性能路线图的路标。
10. **性能靠利用数据特征，而非通用优化**（前半有序/遍历复用/管道）。rpx 落点：
    远期；但「管道」（一次遍历挂多运算）对 rpx-ds 大 CSV 取数同样适用——
    多个数据集引用同一文件时共享一次 IO。
