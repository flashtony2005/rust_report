# 范式转变：从「人适配工具」到「系统自我驱动」的 Agent 原生业务架构

> **“我们不该手动给 AI 写提示词，而是要搭建一套能够自我驱动的系统。人定义目标，系统驱动自己。”**

---

## 1. 痛点觉醒：自研工具的「可用」与「难用」

很多团队在业务系统建设中都会产生一个直觉：
> *“有需求，那就手搓一套系统；能力到位，自研好像什么都能做。”*

在传统 BI 与报表引擎的建设中，技术团队自研了强大的底层报表引擎，实现了 60+ 种复杂报表能力、动态行列扩展、交叉多维汇总、公式级联与多端高保真排版。在技术 Demo 阶段，一切运算、渲染与可视化都能完美跑通。

但真正落入实际生产时，立刻遭遇了最现实的鸿沟：
* **业务人员没有意愿、也不应该花费大量时间去学习报表引擎的语法、参数排布与网格配置**。
* 当系统需要用户先去理解“主格模型、左父格、上父格、交叉透视配置、SQL 关联语法”才能产出一张报表时，这个系统就陷入了**「工具很强，但人被工具绑架」**的死胡同。

---

## 2. 核心转变：底层报表引擎的调用主体，从「人」换成「Agent」

底层报表引擎绝不是无用资产——相反，它是整个体系最核心的执行能力底座。**它没有被抛弃，只是它的“直接用户”从终端业务人员，换成了 AI Agent。**

```
【旧范式：人适配工具】
业务用户 ──(学习配置/手写公式/手动拼装)──▶ 复杂报表引擎 ──▶ 交付报表
  ▲                                             │
  └────────────────── 繁琐试错与反复配置 ─────────┘

【新范式：系统自我驱动】
业务用户 ──(一句话自然语言表达业务目标)──▶ [ Agent + 领域本体 Ontology ]
                                                 │
                                                 ▼ (自主意图分诊 / 口径解析 / 约束校验)
                                          [ 编译器生成 Safe CTE 执行计划 ]
                                                 │
                                                 ▼ (驱动底层报表引擎)
                                          [ 规范 JSON 报表 (rpx-report/v1) ]
                                                 │
                                                 ▼ (多表层投影)
                                     Univer / Web / PDF / Excel
                                                 │
                                                 ▼
业务用户 ◄───(人类专家在设计器中审阅并确认 HITL)──────┘
```

---

## 3. 语义护城河：为什么必须要有领域本体 (Ontology) 与业务上下文

如果仅仅让大语言模型随意去调用报表模板或手写 SQL，系统必然遭遇**“幻觉”**与**“口径翻车”**（如多对多关联产生的笛卡尔积乘数爆炸、退货未剔除的假营收、跨业务实体混淆）。

因此，必须在 Agent 与底层引擎之间筑起**领域本体 (Ontology)** 语义底座：
1. **实体与关系网络 (Entities & Relations)**：严格界定客户、订单、履约、财务账户之间的拓扑图谱，拒绝非法 JOIN；
2. **度量标准口径库 (Metric Calibers)**：固化核心指标代数公式（如 `SUM(amount) - SUM(refund)`），防范自由发挥；
3. **业务规则与约束 (Business Constraints)**：如防翻车独立预聚合 CTE、安全过滤条件；
4. **上下文动态裁剪 (Context Pruning)**：根据用户一句话动态装配当前库表的元数据子集，不给 LLM 注入噪声。

本体相当于给 Agent 一套**统一的业务语义词典与安全宪法**，让它看得懂业务需求，算得出准确数据。

## 4. 复杂度守恒定律：复杂度的转移与水下冰山

**复杂度并不会凭空消失，它只是发生了转移。**

* **旧系统**：将复杂度推给前端用户。用户要懂技术概念、要学 prompt、要一轮一轮在聊天框里跟 AI 纠错、人夹在循环中间当黏合剂。
* **新系统**：将复杂度完全沉淀到系统底层——
  * **人表达意图**：业务人员只说一句话：“华东各品类销售额交叉表（自动归因异动）”。
  * **水面之下的自我驱动**：
    1. **三层意图分诊 (L1 语义 / L2 词表 / L3 物理约束)** 自主探查上下文；
    2. **受控编译**：生成防翻车的 Safe CTE 执行计划；
    3. **报表引擎执行**：推导网格排布，输出从头到尾一致的单据级规范 JSON (`rpx-report/v1`)；
    4. **Agent 自动公式编译**：推导行列聚合公式并记录 `formula_audit` 审计依据；
    5. **多表层投影**：同一份 JSON 自由投影为 Univer 电子表格、响应式 Web、PDF 打印套打或 Excel 工作簿；
    6. **人类在回路确认 (HITL)**：人类专家只在设计器中审阅确认，完成闭环。

---

## 5. 结语：下一代业务系统的核心范式

> **下一代业务系统，核心不是做一个功能丰富、给人操作的工具；而是搭建一套可以自我提示、自我执行的 Agent 系统。**
> 
> **人定义目标，系统驱动自己。**
