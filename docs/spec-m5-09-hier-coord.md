## 0. 可信度与基准声明

1. **唯一 oracle = 产品引擎**（ReportLite，`CalcProbe.calc` + FileDataSet 离线 CSV），  
   与现有 35 个 `engine_*` 夹具同一条管线（`EngineModels.build` → `ReportUtils.write`  
   → `calc` → `expected.json`）。NopReport 是第三方按用户文档推理的重写（作者自述），  
   其坐标基准、越界行为、序号起点均可能与产品不同 ⇒ 不能当基准。
2. 本文件的表达式与期望值在探针跑通前一律是**待验证假设**，涉疑处标 ⚠。
3. 探针只 dump 不断言；结论先写 `tests/fixtures/RUNLOG.md`，再据此生成一等夹具。
4. 每条夹具至少 **2 格手算断言**（不依赖产品输出），其余全网格对拍。

### 2.2 布局坑（探针踩出来的，生成夹具必须遵守）

1. **产品 FileDataSet 的 `.csv` 是 TAB 分隔**（`engine_crossalign.csv` 实测 `\t`，GBK）。写逗号会导致整列丢失，报「无法识别的表达式：region」——不是表达式问题。
2. **扩展会移动固定格**：模板 (8,6) → 计算态 (10,7)；(10,2) → (12,2)。断言必须用计算态坐标。
3. **列带内的格会横向复制**：模板 (10,2) 的 `FIXA` 在计算态出现两次（(12,2)+(12,3)）；固定探针格必须放在带外列（本探针用 col 6，仅一份）。
4. **"越界"有两种语义，夹具必须分开断言**：有主格但索引越界 → null；当前格没有该主格 → 报错。二者不可混为一谈（08 vs 06）。
5. **`!` 倒数坐标产品不支持**——Nop 扩展，已证伪，不进夹具（记为带账：产品无倒数坐标）。

### 2.3 合并区探针（`ProbeHc4`，11 例，2026-10-20）

上一轮把 B2:C2 合并塞进 3×3 交叉矩阵时，产品把横向扩展弄歪了（两列都出 `E/A`）、
固定格坐标落空 —— 症结是**双向扩展 + 合并区叠加**。改用**只纵向扩展**布局后全部跑通：

```
A2 纵向（ds1.select(dept)，D1/D2/D3）    B2:C2 横向合并，B2 = A2+"#"
```

| 问 | 结论 | 证据（计算态） |
| --- | --- | --- |
| Q1 锚点取值 | `B2[A2:k]` 取第 k 个实例 | (10,6)=`"D1#"`；(10,7)=`"D2#"`（另一例） |
| Q2 延续槽取值 | `C2[A2:k]` **读锚点值**（两张矩阵都把它当别名） | `C2[A2:2]`=`"D2#"`、`C2[A2:3]`=`"D3#"` |
| Q3 格集计数 | 延续槽**不被重复计数** | `count(C2[`0]{})` = `count(B2[`0]{})` = **3** |
| Q4 合并是否随扩展复制 | **只有第 1 个实例保留合并**（(2,3) colMerge=2；第 2/3 实例 colMerge=1，各自独立 src） | src(3,3) cm=1；`merged` 段仍按每个实例报 cm=2 |

两条布局坑：

1. **`B2[A2]{}`（有主格、无序号）在固定格报错**「"[]"位移对象超出范围」——固定格没有 A2
   主格实例。要数全量必须写根坐标 `` count(B2[`0]{}) ``。
2. **合并区不能与横向扩展同带**：`B2:C2` 合并 + B1 横向扩展 ⇒ 产品把两列都填同一个值，
   横向扩展被扭曲。合并夹具必须单方向扩展。

原探针日志：`tests/fixtures/out/hc4_probe.log`；摘要在 `out/hc4_summary.txt`。

| R5 | rpx 无 rowDescendants/colDescendants 映射 | 坐标定位需自建「主格 → 实例列表」索引（或沿 head 链 + 矩阵扫描）；性能与内存一次定案 |

## 8. 本轮不做

子报表模型、定位与拉伸、跨页坐标（求值发生在分页前，无此形态）、  
NopReport 的 Delta/Excel 模板形态、格集元素顺序（产品未定义则记为怪癖，不实现）。

### 9.2 可迁移到 rpx 的四条

1. **编译期建节点**：坐标在解析期变成 AST 节点，求值期只做定位——避免每格重复解析字符串。
2. **主格链定位**：首坐标沿 head 链上溯到同名主格、再取该主格下的全部实例；后续坐标在上一级结果里继续下钻——与 rpx `heads/` 的 `left_head`/`top_head` 链同构。
3. **行列求交**：行坐标与列坐标分别解析成实例列表再交集——交叉表单元格的定位方式。
4. **上下文相关降级**：操作数位置取首值、函数实参位置保持集合——rpx 已有单值/集合双态，落点应在求值前的判定层（类同 `expr/classify.rs`）。

### 9.3 不可迁移 / 禁止照抄的三条

| 点              | Nop 做法                          | 为什么不能进 rpx 夹具                                  |
| -------------- | ------------------------------- | ---------------------------------------------- |
| 1-based + 越界空集 | `pos-1`；`pos>size → 空集`         | 产品序基准未探针（P4/P8），可能 0-based 或抛错                 |
| `!` 倒数坐标       | `A2:!-1` = 倒数第 1 个              | 润乾手册无 `!` 形态，是 Nop 扩展；产品不支持则禁入夹具               |
| 条件格集用 lambda   | `{cond}` 编译成 predicate，无 `$` 语法 | 润乾 `{cond}` 的 `$` 有明确语义（当前格主格），不能以 lambda 语义替代 |

另：**NopReport 没有 `&` 运算符实现**（`&` 在其 Excel 语法里是字符串连接）——`&` 只能靠产品探针（P7）+ 手册语义，参考实现为零。

### 9.4 对夹具清单的两处修正

- **P4 / 夹具 #2**：Nop 解析器把负号自动标 relative（`A2:-1` 是相对，不是倒数），倒数要写 `!`——三种写法必须在探针里分开记录。
- **新增 R5**：rpx 没有 `rowDescendants`/`colDescendants` 映射，坐标定位需自建「主格 → 实例列表」索引；这是本项最大实现工作量，不是语法解析。

### 10.2 Move：坐标语法与解析（逐条对上探针）


- `setParameter`（`Move.java:59-109`）：`;` 切**行/列坐标**，`,` 切**主格链**，`:` 切 `主格:位置`。
- `getScopeMove`（`Move.java:111-175`）：
  - `+n`/`-n`/`0` → **相对**（type 1）；
  - 纯数字 `n` → **绝对**，内部存 `n-1`（用户 1-based，**与探针一致**）；
  - 缺省 → **当前**（type 2）；
  - 解析失败 → `Move.formatError`（探针 `A2:!-1` 的「位置参数格式不正确」即此，`!` 无分支）。
- 坐标分量 `IIIIllIIlIIlIIll`（混淆类）：`position:int` + `source:ExtCell` + `type:0/1/2` + `resolved:bool`。
- 快路径 `_$1(CSVariable)`（`Move.java:181-273`）：单轴 ≤2 个坐标且 `isLineCoord`；按 `extendType` 17/19/其它取 `leftHead/topHead`；**双坐标 = 范围**，用 `Sequence.getCellSeq` 算 `lCount/tCount`，返回四参 `CSVariable`。
- 一般路径 `_$1(CSVariable, ctx)`（`Move.java:275-418`）：
  - 相对坐标解析时 `head == null` → **抛 `"[]" + Move.outOfRange`**（探针 08/14 原文）；
  - `getExtCell(position)` 越界 → **返回 null**（探针 06 首行、10 的 `[A2:99]`）；
  - 探针观察到的「二分语义」在源码里就是这么写的，**不是巧合**。

### 10.3 Select：格集与 `$`

- `calculate`（`Select.java:29-43`）：左侧必须是 `CSVariable`；`getCells(null)` 展开实例。
- `_$1`（`Select.java:48-79`）：无参数 = 整集；有参数 = 逐格 `cs.setCurrent(cell)` 求谓词，`false` 剔除；非布尔 → `function.paramTypeError`。
- **`$` 的实现**：`saveCurrent()`（`:55`）+ `CSVariable(cell,true)` → `cs.getSavedCurrent()`（`CSVariable.java:102`）。`$B2` = **保存的当前格**的 B2 主格——与 `$`（isSaved）同源，不是独立语法。

### 10.4 Address：`&` 序号

- `calculate`（`Address.java:90-124`）：右操作数须为 `CSVariable` 或 `ExtCell` 列表。
- `_$1`（`Address.java:27-88`）：`source.isLeftHeadOf(current)` → 在 `leftHead` 实例表定位：≤10 线性 `isLeftHeadOf`、>10 按 `row` **二分**；返回 **i+1**（1-based）；否则 `isTopHeadOf` 同理；都不中 → `Address.isNot ... parentCell`（探针 16 原文）。
