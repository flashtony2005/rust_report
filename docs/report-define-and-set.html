0. 一张图看懂「定义」与「设」

定义 JSON唯一事实源
（可手写 / 面板产出 / 编辑器导出）
→
POST /api/renderreport + dataset
+ params（multipart）
→
渲染引擎表达式求值 · 扩展 · 合并
→
Univer 快照上画布 · 可编辑
→
导出 / 入库「导出 JSON」下载
「另存为」→ .rpx

设计器闭环：面板与画布的改动补丁进持有的定义 JSON → 点「渲染」用最新 JSON 重渲染（补丁不丢）→「导出 JSON」拿回文件或「另存为」入库。

核心口径：定义 JSON 是唯一事实源 —— 手写、面板产出、 编辑器导出都是它；渲染只是它的一次快照。前端设计器不重建 JSON、只对它打补丁 （快照有损：style_json 只暴露 9 字段，边框/format/indent/rotation/extend_mode/ print_setup 都不在快照里 ⇒ 反推会静默抹掉用户手写字段）。

1. 报表如何定义（定义 JSON 全字段）

1.1 顶层结构

顶层字段必填语义
version可选契约版本（当前 1）
grid必填{rows, cols} 网格尺寸（决定报表骨架）
cells[]可选格子数组：内容（text/expr）+ 样式 + 结构（合并/扩展）
datasets[]可选数据源（sql 或 file 之一）；表达式里 ds1.xxx 的来源
params[]可选参数声明（渲染时给值）；@名 在表达式里引用
row_props[]可选{row, height?, break_page?} 行属性（height 单位 mm）
col_props[]可选{col, width?} 列属性（width 单位 mm）
print_setup可选打印设置 16 字段（纸张/边距/分页/缩放/版面/打印布尔）

1.2 grid（网格尺寸）

报表骨架 = {rows, cols}。cells[] 的坐标、row_props/col_props 的下标都必须在 1..=rows/cols 内。⚠ 缩小 grid 前必须校验越界 —— 既有声明（含合并矩形） 越界 ⇒ 服务端 400；前端面板显式报错（含首个越界位置），不静默截断。

1.3 cells[]（格子：内容 + 样式 + 结构）

字段类型语义
row / col整数 必填 坐标 1 起（1..=grid.rows/cols）—— ⚠ 快照输出是 0 起，别混
text字符串静态文本；与 expr 互斥
expr字符串值表达式（如 ds1.select(region)、@topN、B2*2）
bold / italic / underline / font_name / font_size / fore_color / back_color —7 个样式字段（逐字段独立：给了才改，不打回缺省）
border对象四边 {left?,right?,top?,bottom?}，线型 5 种（none/dotted/dashed/solid/double）
format字符串数字格式（如 "#,##0.00"）
indent / rotation数字缩进（≥0）/ 旋转角（度，≥0）
extend_mode枚举"vertical"(18) / "horizontal"(19)；缺省 16（运行时自动升竖向）
merge对象{rows, cols} 合并矩形（锚点格声明）
merge_same枚举"vertical"(98)/"horizontal"(99) 同值合并
三条硬约束（写错就 400，不猜）
  1. 坐标 1 起：grid 与全部 cells/row_props/col_props 用逻辑坐标； 快照输出与 xlsx 读回是 0 起 —— 差一格不报错，只是落到隔壁格。
  2. text 与 expr 互斥：都给报错；都缺 = 空白格（合法：合并锚点/占位）。
  3. 合并矩形内的非锚点槽不得带内容：带 text/expr 报错；空壳容忍 （Univer 导出会把矩形内每个槽都列出来，这是自然形态）。声明顺序无关（两趟解析）。

1.4 datasets[]（数据源）

每条给 sql 或 file 之一（互斥）：

形态字段要点
sql{dsn, sql} dsn 是连接名（服务端 serve --datasources 注册，凭据不进模板）；sql 查询语句
file{file_name, encoding?} CSV 文件；file_name 须与渲染时上传的文件名逐字一致；encoding 缺省 GBK

数据集名（name）就是表达式里 ds1.select(...) 的前缀。 重名只告警不拦截（服务端口径）。

1.5 params[]（参数）

每条 {name, data_type, default?, kind?, description?}：kind: "dynamic" = 渲染时必须给值（is_static=false）；静态参数有默认值。 ⚠ 声明 ≠ 给值：渲染时未传的动态参数会 400（点名缺失参数名），不是静默取 null。 前端「另存为」后按 GET /reports/{id}/meta 刷新表单，动态行标「动态」。

1.6 row_props[] / col_props[]（行列属性）

{row, height?, break_page?} / {col, width?}。height/width 单位是 mm（与 .rpx 一致：缺省行高 8mm、列宽 25mm）；服务端按 96dpi 换算成 px （8mm→30.24px、25mm→94.49px）。字符串形态的 height 契约允许（数字→字面量、字符串→当表达式透传）。

1.7 print_setup（打印设置 16 字段）

纸张（paper_width/height，缺省 A4 210×297mm）、四边距（19/19/25/25mm）、 row_num_per_page（20）、copy_count（1）、zoom_scale（100）、 table_column_num/layout_rows/layout_cols（1）、4 个打印布尔（缺省 false）。 未声明 = 契约缺省（不显式设也生效）。

3. 如何在前端设（Web 设计器）

3.1 页面结构

顶栏（文件选择 + 渲染 / 另存为 / 导出 JSON）· 参数表单 · 右侧六个停靠面板 （样式/属性/行列/参数/数据集/报表设置）· 状态栏 · Univer 画布容器。 「导出 JSON」按钮在无 .json 源时置灰（能力边界可见，而不是点了才报错）。

3.2 六个面板与补丁语义

面板（右侧停靠）覆盖字段补丁方式读方向
样式字体族/字号/颜色/粗斜下划线（7 字段） 逐字段补丁，改回缺省 ⇒ 删键Univer 活态 + JSON 缺省
属性边框四边 / 数字格式 / 旋转 逐键补丁（边框 4 边各自独立）定义 JSON（快照不含这三项）
行列row_props/col_props + grid 改行高只动该行 height；条目无属性 ⇒ 删整条；grid 缩小先校验越界 定义 JSON（mm 显示，96dpi 落地画布）
参数params[] 声明 + 渲染时给值 入库后按 /meta 整体刷新表单服务端声明（权威）
数据集datasets[] 整条替换（面板编辑的是完整一条，旧键整体作废）定义 JSON
报表设置print_setup 16 字段 逐键补丁，缺省即删键；未声明显示契约缺省定义 JSON

画布本身 = 内容编辑：直接改单元格 ⇒ SheetValueChanged 事件 ⇒ 只补改过的那一格 （designer.ts 的四条契约前置错误：越界 / 合并内非锚点 / expr 覆盖 / 网格边界）。

3.3 完整闭环（六步）

步操作背后发生什么
1选文件（.json 或 .rpx + CSV）→ 点「渲染」 POST /api/render（multipart）拿快照上画布；同时读定义 JSON 文本持有 （只有 .json 有；.rpx 是二进制，编辑面不可用并显式告知）
2右侧六面板设定样式/属性/行列/参数/数据集/报表设置 每个面板的改动逐键/整条补丁进持有的 JSON（补丁不丢的唯一保证：始终持有原始定义）
3画布上直接编辑单元格内容 SheetValueChanged → applyValueEdit → 只补这一格；越界/覆盖 expr 等失败显式上屏
4点「渲染」 用当前持有的 def 重渲染（刷新画布，补丁不丢）—— 不是重新读文件
5点「另存为」 POST /reports（字段名 file）入库拿 id → 按 /meta 刷新参数表单
6点「导出 JSON」 downloadDefJson 下载定义文件（无 .json 源时按钮置灰）——编辑面的唯一出口

3.4 为什么「持有原始 JSON 打补丁」

快照有损：服务端 style_json 只暴露 9 个字段 （bl/it/ul/ff/fs/cl/bg/ht/vt）；边框/format/indent/rotation/extend_mode/print_setup 不在快照里。⇒ 拿 Univer 当前状态重建 JSON 会把这些静默抹掉。 正确形态：渲染时读定义 JSON 文本持有，所有编辑只对持有的那份打补丁 （纯函数、只动该动的键、改回缺省删键、幂等）。同理，内容编辑只跟事件只补一格： 整体回灌会把 "0123" 这类值被 Univer 按数值归一化，没碰过的格也被改坏。

4. 从零设定一张工资表（端到端配方）

步定义 JSON 侧前端操作
1grid: 3×2；表头两格 text新建/选 JSON 文件渲染
2datasets[0]：{name:"ds1", sql:{dsn:"demo", sql:"SELECT name, salary FROM emp ORDER BY id"}} 数据集面板新增一条（校验镜像服务端：dsn/sql 必填）
3两格 expr: "ds1.select(name/salary)" + extend_mode:"vertical" 画布直接输入表达式；属性面板设扩展模式
4末行 expr: "ds1.sum(salary)"画布输入聚合表达式
5（可选）标题格 bold/font_size；行高 row_props 样式面板 / 行列面板
6—「渲染」验证 → 「另存为」入库 →「导出 JSON」拿回文件

判定依据：open_bytes(to_bytes(build(json))) == build(json) —— 定义 JSON 经 服务端解析 → .rpx 写回 → 重解析必须逐字节相等（往返判据，服务端测试 definition_roundtrip.rs 同一条）。
