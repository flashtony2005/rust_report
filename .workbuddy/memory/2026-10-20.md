## rpx-semantic 功能定义（回答「功能是什么」）
- 定位：报表引擎的**创作侧知识库 + 生成管线**（不做查询层）；LLM 只在这一层出现，引擎/服务端零 LLM 依赖。
- 五个功能块：①内省 scan（rpx-ds SqlSource 只读连 SQLite/PG/金仓，扫表/视图/列/类型/可空/主键/候选外键 + 轻量采样行数/枚举 Top-N/数值日期范围，产可重扫 catalog 带结构指纹）②语义目录（表业务名/同义语、列中文名/单位/枚举字典/敏感标记、关联含 `emp_id==A3` 跨集关联式、口径指标=表达式+过滤、术语表；CRUD+版本+变更检测；坑库条目 codify）③例库（需求描述+定义 JSON+数据集 SQL+数据源指纹+渲染基线+标签+来源；过引擎渲染+夹具才入库；相似检索/导出 few-shot/结构变标 stale）④生成管线（需求→目录检索→例库 top-k→LLM→定义 JSON→schema 校验→引擎渲染→夹具对拍→错误回灌重试≤N→入库）⑤接口面（先 CLI：`rpx semantic scan/dir/example/gen`；JSON 可进 git；HTTP/设计器面板后置）。
- 数据模型 6 表：data_source / ds_table / ds_column / ds_relation / ds_metric / example（术语可并 metric 或单开 term）。
- 红线：不做通用 BI 语义层（口径只存表达式不承担计算）、多租户、渲染链依赖、客户业务库建表。
- 下一步：等用户确认范围 → 写 `docs/spec-m8-semantic.md`（现有 spec 到 m7，编号顺延）。

## 定位澄清（回答「6 张表是不是元数据库」）
- 6 表存的是**报表域元数据 + 语料**：技术元数据（data_source/ds_table/ds_column/ds_relation）+ 业务元数据（中文名/同义语/metric 口径/术语）+ 语料元数据（example，带可执行定义 JSON）。
- 但**不是元数据管理平台**（非 Atlas/DataHub 类）：不做采集代理/血缘图谱/权限治理/多系统接入；是单引擎伴生库（side-car），物理上只是 semantic.db，第一阶段可纯 JSON 文件（catalog.json + examples/*.json）。
- 本质差别：普通元数据库是静态目录（给人看），此处是活知识（参与生成 + 结果回流 + 反哺下次生成）；对外口径叫「语义层/报表知识库」，不按元数据平台立项（会滑向一次性定制反例）。

## 与 ontology 的关系（回答「是不是同样的思想」）
- 思想同源：都是把隐含语义显式化成机器可读模型（类/关系/约束）；6 表=类（表/列/指标/例）+ 关系（belongs-to/joins-on/derived-from）+ 约束（类型/枚举/口径表达式）。
- 只取一半：要「显式化」不要「形式逻辑推理」——不上 OWL/RDF/推理机，不改开放世界假设；定位**轻量本体 pragmatic ontology**（封闭、单引擎、从库反推、边用边补）。
- 生命周期同构：本体治理的难点在概念漂移/版本/废弃，我们的链路 scan（采集）→dir（补语义）→example（使用+反馈）→变更检测/stale（治理）→version（历史）即语义资产生命周期。
- 红线：不按 ontology 立项（本体库+推理+行业标准），否则重、慢、每客户要建模专家=边际成本爆炸；LLM 时代本体作「上下文/约束」而非「推理引擎」。

## 调研：结果视图改样式 → 打印预览反映（23:26-23:35）
- **实测两条关键事实**（探针在结果视图里跑）：

  C 服务端 styleOverrides 重算（PDF/HTML 全一致但最贵）。

## Univer Pro 打印原理（查官方文档，23:30）
- 形态：商业闭源插件 `@univerjs-pro/sheets-print`（也打包进 `preset-sheets-advanced`）；**不是**服务端导出，走**浏览器打印**。
- API：`FWorkbook.openPrintDialog()` / `updatePrintConfig(layout)` / `updatePrintRenderConfig(render)` / `print()`；
  另有 `saveScreenshotToClipboard()` 与 `FRange.getScreenshot({includeHeaders})` —— 后者**需 license**，返回 base64，说明内部会把页渲染成位图。
- **两层配置**是关键设计：layout（area/paperSize/scale/freeze/margin/分页）= 排版域；render（gridlines/hAlign/vAlign/headerFooter/水印）= 绘制域。
  事件 `BeforeSheetPrintOpen/Confirm/Canceled` 可拦截或二次加工。
- 与我们对照：我们把「分页」交给 Rust 引擎（按报表语义），Pro 把分页放在插件里按 Excel 口径算；但**打印读活态工作簿**这点值得学
  —— 这也是「结果里改样式、预览要跟着变」的正确解法（读活态而非静态 run 快照）。
