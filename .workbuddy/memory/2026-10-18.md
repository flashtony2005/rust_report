## examples/r-model：新增七份典型业务报表（commit `ee1e686`）

- 用户问「gallery.html 能不能增加多典型的报表，为了给客户展示表格的能力」；原 19 份偏引擎特性，缺一眼认得的业务成品。新增独立分组「典型业务报表」，catalog 从 19 → 26 份，全部 checks 通过。
- 新增：`income-statement`（利润表·两期）、`balance-sheet`（左右双栏+平衡校验）、`payroll`（部门分组工资表）、`stock-ledger`（进销存）、`cash-journal`（日记账·余额逐行结转）、`sales-order`（发货单）、`ar-aging`（账龄分析），各带 CSV + 模板 + 独立预期 checks；打印预览实测均 A4 单页 794×1123。
- **模板写法三条硬约定（踩坑换来，已写入 README）**：
  1. 同一行只有一列 `extend_mode=vertical`，其余列 `none` + `left_head` 指向该驱动格；多列都设 vertical 会扩展相乘（6 行明细炸成 **798 行**）。
  2. 计算列写数据集表达式（`pay.select(base+bonus)`）；扩展块内写 `C4+D4` 会被当整列集合相加 → `UnsupportedExpr`。
  3. 扩展块与合计行之间不能留空模板行，否则空行算进块内、合计被推下去（sales-order 因此多出 5 个空行）。
- **border 不落地（实测）**：JSON 定义里的 `border` 既不进 Univer 快照（style 只有 bg/bl/cl/ff/fs/ht/vt/n），也不进 xlsx（`borders count="1"` 只有默认定义，单元格无 s 属性）。模板因此不写边框，视觉层次靠表头 `#2C4A5A` 与合计行 `#F1F4F7` 底色；否则会留「设了却没生效」的假象。
- 宏只作用于表达式、**不作用于 text**：`${openingBalance}` 写在 `text` 里会原样上屏，故日记账标题的期初金额直接写字面量，宏只给公式用。
- 其他：`ds.sum(field, cond)` 可按条件汇总静态行（利润表 11 个科目）、`sum(B4[\`0]{})` 才是整根格集（`ds.sum` 在组内上下文只汇总当前组，占比列一开始全是 100%）、`E4[-1]` 余额结转要求列号真实存在（写错列号会报 `CircularRef`）。
- 数字格式与列宽联动：`#,##0.00` 在 23mm 列宽里显示 `####`，资产负债表改用 `#,##0`；总列宽控制在 ≤172mm（A4 减默认左右边距）才不会横向分页。

## CLI 准确性缺口实测 + 新技能 `rpx-report-authoring`

- 用户问「如何用 cli 准确生成报表 / cli 要不要增强 / 能不能做 skill 调用 cli」。
- 用 8 组最小对照模板（同一可用基线，每次只改一处）实测，结论：**CLI 能保证"算得出"，不能保证"打得对"**。
- 静默失败清单（全部实测复现）：
  1. CSV 不写 `delimiter` → `validate` 仍 `valid:true`，`run` 报 `CALCULATION_FAILED: Engine(UnknownCell { id: "ds.customer" })`，**不提示分隔符**；只有 `dataset inspect` 能看到 `columns: ["customer,amount"]` 一整串。
  2. `text` 里写 `${period}` → 原样上屏，零警告（宏只在 `expr` 替换）。
  3. 单元格写 `border: solid` → xlsx `styles.xml` 只有 1 个 `<border>`，与不写完全一致（写了等于没写）。
  4. 扩展块与合计行之间留空行 → 多一行空行、合计被推下，静默。
  5. 同排多个 `vertical` 且无 `left_head` 父子链 → 扩展相乘（真实案例 798 行）。
  6. `ds.select(...)` 放非扩展列 → 返回 `"差旅,招待"` 逗号串、金额算成 0，行数不变不报错。
- **重要纠正**：同排多个 `vertical` 不是绝对禁止——`complex-cell-calc` 用 `A6 group(region)` / `B6 group(department) left_head=A6` / `D6 group(employee) left_head=B6` 构成父子链，是合法且正确的两级/三级扩展。判定标准是「是否串成父子链」，不是「一行只能一个」。

## 0.16.0 导出 xlsx 列宽 —— 修 Excel 显示 `####`

- 用户报「运行后数据显示 ####，把格子拉宽点」。取证结论：`####` **只可能来自 Excel/WPS**——本仓 HTML/PDF 产物 grep 零 `###`，Univer 1.0.4（`@univerjs/engine-render`、`sheets`）里没有井号填充逻辑；Excel 只对**数字/日期**放不下时画 `####`（文本会溢出到邻格）。旁证：10-18 早些时候写典型报表时就记过「`#,##0.00` 在 23mm 列宽里显示 `####`」。
- 根因两层：① 数据出口 `to_xlsx` **完全不写 `<cols>`**（Excel 默认 8.43 字符≈64px）；② `print-xlsx` 虽写列宽，但只按模板 mm 换算、不看内容。
- 修复：新增 `crates/rpx-export/src/widths.rs`（`base_px` / `fitted`），两种 xlsx 出口统一走 `xlsx::write_widths`。口径：模板列宽为底；**只对数值格**加宽（文本格 Excel 会溢出，不会 `####`）；合并区按整段宽度算、缺口平均摊到跨度内可见列；隐藏列跳过；未写列宽按 64px 兜底。上限 255 字符。
- 估宽两个坑：① 格式按**格**声明，与值的存储类型无关——`Int` 的 1286000 在 Excel 显示成 `1,286,000.00`，首版只对 Double/Float 套 pattern，漏加宽；② Excel General **会按列宽收减小数位**，只有整数部分放不下才 `####`，按全精度估宽会把列撑成两倍。
- `numfmt` 从 `rpx-runtime` 移到 `rpx-engine`（导出面按 G8 分层矩阵不能依赖 runtime），`rpx_runtime::numfmt` 路径保留。
- 证据：8 份模板端到端复算「需宽 vs 导出宽」= 0 格放不下；ar-aging 第 2 列 13.3→15.0 字符（放 `1,286,000.00`）、第 4 列 10.1→11.7。新增 7 条单测 + 3 条读回 `<cols>` 的集成测试 `tests/xlsx_widths.rs`（dev-dep `zip`）。
- 已知非本次引入的偏差：`rust_xlsxwriter::set_column_width_pixels` 落盘比模板宽约 +0.7 字符（它按 px/7 换算），print-xlsx 一直如此。
- 版本 0.15.0 → **0.16.0**，G1–G9 全绿，`~/.local/bin/rpx` = 0.16.0。
